# 카드 랩 · 라이브 바카라 테이블

실시간 멀티플레이어 바카라 웹사이트입니다. **가상 칩 전용이며 실제 결제·환전 기능은 없습니다.**

## 구성

- `server.js` — Express + Socket.io 백엔드. 서버가 딜러 역할을 하며 모든 접속자에게 같은 카드를 동시에 전송합니다.
- `public/login.html` — 회원가입(승인 대기) / 로그인 페이지
- `public/game.html` — 실시간 게임 테이블
- `public/admin.html` — 관리자 전용: 가입 승인, 칩 충전/차감
- `data/users.json` — MongoDB를 연결하지 않았을 때만 사용하는 로컬 백업 저장 파일

## 규칙 요약

- 8덱 슈, 2~9는 숫자 그대로 · 10/J/Q/K는 0 · A는 1, 합이 10 이상이면 뒷자리만 사용
- 베팅 15초 → 카드 공개 8초 주기로 자동 진행
- 메인 베팅(플레이어 1:1 / 뱅커 0.95:1 / 타이 8:1) 필수, 페어 사이드 베팅(11:1) 선택
- 타이가 나면 메인 베팅(플레이어/뱅커)은 환불, 페어 베팅은 각각 독립 판정
- 라운드가 끝나고 순이익이 가장 큰 사람이 있으면 모두에게 "OOO님이 NNN칩을 따셨습니다" 공지
- 경기 기록 동그라미는 최근 44개까지만 표시
- **가입 축하 칩 없음 · 셀프 충전 없음** — 관리자가 승인하고 충전해줘야 플레이할 수 있음

## 회원가입 · 승인 흐름

1. 누구나 아이디/비밀번호로 가입 신청 가능 (실명·학년·반 등 개인정보는 받지 않음)
2. 일반 가입은 **관리자 승인 전까지 로그인 불가** — "승인 대기 중" 상태로 남음
3. 회원가입 시 **관리자 코드**(`.env`의 `ADMIN_SIGNUP_CODE`)를 입력하면 승인 없이 즉시 관리자 계정으로 가입됨
4. 관리자는 `admin.html`에서 대기 목록을 보고 승인/거부 가능
5. 관리자는 유저별로 칩을 **충전(+)** 하거나, 실수로 잘못 넣었을 때 **차감(−)** 할 수 있음 (차감 시 잔액이 음수가 되는 조작은 자동 차단)

## 로컬에서 실행하기

```bash
npm install
cp .env.example .env
# .env 파일을 열어 JWT_SECRET, ADMIN_SIGNUP_CODE를 자신만 아는 값으로 바꾸세요
npm start
```

브라우저에서 `http://localhost:3000` 접속 → 로그인 페이지로 자동 이동합니다.
회원가입 화면에서 관리자 코드를 입력해 첫 관리자 계정을 만드세요.

## ⚠️ 데이터가 계속 사라지는 문제 (Render 등 무료 호스팅)

Render 같은 무료 호스팅은 서버가 재시작/재배포될 때마다 디스크를 완전히 새로 만듭니다.
`data/users.json`처럼 서버가 실행 중에 직접 만든 파일은 이 과정에서 통째로 사라집니다 — 코드 버그가 아니라 무료 플랜의 저장 방식 자체가 그렇습니다.

**해결책: 무료 MongoDB Atlas를 연결하면 서버가 몇 번을 재시작해도 데이터가 유지됩니다.**

1. https://www.mongodb.com/cloud/atlas/register 에서 무료 계정 생성 (신용카드 필요 없음)
2. "Shared" / **M0 Free** 클러스터 생성 (지역은아무 곳이나 무료로 표시된 곳 선택)
3. Database Access에서 유저 이름/비밀번호 생성
4. Network Access에서 `0.0.0.0/0` (모든 IP 허용) 추가 — 배포 서버가 어디서든 접속 가능하게
5. "Connect" → "Drivers"에서 연결 문자열(`mongodb+srv://...`) 복사
6. 이 문자열을 `.env`(로컬) 또는 Render의 Environment 변수에 `MONGODB_URI` 라는 이름으로 등록

`MONGODB_URI`가 설정되어 있으면 서버는 자동으로 DB를 사용하고, 시작 로그에 `[DB] MongoDB 연결 완료`가 찍힙니다.
설정하지 않으면 로컬 `data/users.json` 파일을 쓰는데, 이 경우 Render 재배포/재시작 시 데이터가 사라질 수 있습니다.

## 인터넷에 실제로 배포하기 (Render.com 예시)

1. 이 프로젝트를 GitHub 저장소에 업로드 (파일들이 저장소 최상위에 바로 오도록 — 불필요한 상위 폴더 없이)
2. Render.com → "New Web Service" → 해당 저장소 연결
3. Build Command: `npm install`, Start Command: `npm start`
4. Environment 탭에서 `JWT_SECRET`, `ADMIN_SIGNUP_CODE`, `MONGODB_URI` 를 설정
5. 배포 후 발급되는 `https://xxxx.onrender.com` 주소를 공유

**Root Directory 설정 관련**: GitHub 저장소 안에 이 프로젝트가 하위 폴더로 들어가 있다면(예: 저장소/baccarat-server/server.js), Render의 Settings → Root Directory에 그 폴더 이름을 정확히 입력해야 합니다. 저장소 최상위에 `server.js`가 바로 있다면 Root Directory는 비워두면 됩니다.

## 알아둘 점

- 이 사이트의 칩은 실제 화폐 가치가 없는 가상의 게임용 수치입니다. 참가자들 사이에서 칩을 실제 돈이나 다른 대가로 교환하지 않도록 안내하세요.
- 무료 호스팅(Render 무료 티어 등)은 일정 시간 요청이 없으면 서버가 잠들었다가 다음 접속 시 다시 깨어나는 경우가 있어, 첫 접속이 몇 초 느릴 수 있습니다.
- `/health` 주소로 접속하면 서버가 살아있는지만 간단히 확인할 수 있습니다 (`{"ok":true, ...}` 응답).
